# Version 0.9.52

Date: 2026-09-09

## Changes

- Added `external/** -text` to `.gitattributes`, so this repository performs no
  end-of-line conversion on submodule content. Submodule bytes belong to the
  submodule.
- Recorded the reason inline as a comment, next to the existing checksum-pinned
  fixture exception it resembles.

## The defect

The mirror workflow materializes each pinned submodule with `git read-tree`,
which copies blobs **by object identifier and applies no filter**. Two files in
the `mta_sim_dataset` submodule are committed there with carriage returns, so
they entered the snapshot index as CRLF bytes.

The repository's own `*.json text eol=lf` rule then applied to those paths on
checkout. That made the working tree disagree with the index it had just been
built from, and the workflow's validation gate —
`git diff --exit-code HEAD -- external/mta_sim_dataset/ZheyuanWu` — reported the
files as modified and exited 1, failing the job before any push. The log shows
the whole file rewritten with identical content, `-` and `+` lines differing
only in line ending, which is the signature of a conversion rather than an edit.

Nothing was published. The workflow prepares the complete snapshot before it
touches a destination reference, so the failure left every Gitea reference
intact, exactly as the publication contract requires.

The same conversion would also have broken the generator's `dataset_manifest.json`
digests, which are SHA-256 values over the submodule's bytes. A byte the mirror
rewrites is a byte that no longer matches its recorded checksum.

## Verification

- Reproduced the failure locally in a disposable repository: a blob committed
  with CRLF under a `text eol=lf` rule makes `git diff --exit-code HEAD` exit 1.
- Replayed the workflow's own sequence — `checkout --detach`, `submodule update
  --init`, `read-tree --prefix`, remove `.gitmodules`, commit — against the
  current commit, then ran the workflow's Python validation gate verbatim. It
  passes, and the snapshot tree contains no Git link.
- Ran the identical replay against the unfixed state as a control: it exits 1
  and reproduces the reported failure. The attribute change is the only
  variable between the two runs.
- `git check-attr` confirms the two previously failing files are now `text:
  unset`, while `.bat` keeps CRLF and the tracked Python, Markdown, and YAML
  files keep LF.

## Limits

The rule is verified by local replay of the workflow's preparation steps.
Authentication, push permission, and the atomic-push verification against the
live host are only proven by running the Action, which the owner triggers. The
carriage returns remain in the submodule's own history; this change stops this
repository from rewriting them rather than editing another repository's commits.
