# Version 0.9.54

Date: 2026-09-09

## Changes

- Deleted every local reference except the snapshot's default branch before the
  publication push, in one `git update-ref --stdin` transaction, so the mirror
  offers exactly `main` and its `master` alias.
- Kept the pruning atomic force push, which now also **removes** the development
  branches and tags an earlier run published to Gitea.
- Stated in the publication contract that Gitea is a single-branch deployment
  mirror, and added the case to the verification requirements.

## The defect

The publication step pushed `refs/heads/*:refs/heads/*` and
`refs/tags/*:refs/tags/*`, so every GitHub branch became a Gitea branch. The
repository currently has twelve branches, including `feat/dashboard-workbench`,
`feat/data-generator-config`, four `codex/` branches and other in-progress work,
plus one malformed tag. All of them were mirrored to the deployment remote.

Gitea is not a backup of GitHub. It is the deployment source that Yunxiao clones,
and it is the target of a deployment webhook. Publishing development branches
there exposes unreviewed work outside GitHub and allows a deployment to be taken
from a branch that never passed validation. Only the default branch is validated
by the snapshot gate, so only the default branch belongs on Gitea.

The `master` alias also no longer depends on GitHub lacking a `master` branch.
It is now written from the same snapshot whenever the default branch is `main`,
because Gitea's alias must track the published commit rather than a GitHub
branch that is not mirrored at all.

## Verification

- Built a disposable source with five development branches and a tag, and a
  destination already holding all of them, exactly as the previous all-branch
  mirror left it. The publication logic reduced the destination from seven
  references to two, deleting `feat/dashboard-workbench`,
  `feat/data-generator-config`, `codex/junk`, `link-campaign-optimizer`,
  `nesbitt/migrate` and the tag, and the reference comparison passed.
- Repeated the run through the gateway retry wrapper added in 0.9.53, confirming
  the two changes compose.
- The workflow file parses as YAML and its publication step passes `bash -n`.

## Limits

The destination is corrected by the next mirror run, not by this commit; nothing
is deleted from Gitea until the Action runs. The Gitee mirror in
`.github/workflows/mirror-to-gitee.yml` still publishes every branch and tag.
That is a different remote with its own contract and was left unchanged here.
