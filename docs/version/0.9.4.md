# Version 0.9.4

Date: 2026-08-12

## Changes

### Documentation governance

- Established specification-oriented programming as a repository rule: `docs/en/` is the ground truth, code implements the specification, and a disagreement between them is a code defect unless the user says otherwise. Agents must not silently rewrite a page to match drifted code.
- Required a `compact` frontmatter field on every page under `docs/en/` and `docs/logs/`, and defined it as a routing signal dense with real identifiers so an agent can read only the `compact` fields to decide which pages a task needs.
- Recorded that each implementation page is the code-level specification for its one or two Python files, carrying the behavior contract those files must satisfy, and that code-level specification must not be collected in a separate project-wide catalog.
- Recorded `modules/mta_strategy_evaluation/` as specified but unbuilt, so its empty directory is not mistaken for the current design.

### Navigation consolidation

- Removed the project-level implementation specification catalog. Code-level specification now lives on the per-file implementation pages.
- Merged the Workspace and Product sections into Overview, shortening the navigation bar from twelve entries to ten. The AMC MTA architecture, capability assessment, and project introduction moved to `docs/en/introduction/`, together with the workspace architecture, development guide, file-management rules, assessment, and development history.
- Deduplicated the overlapping workspace index, documentation index, component inventory, source-tree analysis, and product index pages into the consolidated Overview page, which now carries the reading order, per-topic entry points, workspace partitions, and authority order.
- Added a `compact` field to all 98 documentation pages.

### Code and documentation reconciliation

- Corrected the touchpoint key on the `touchpoint_key.py` implementation page from `PRODUCT:...` to the actual `AD_PRODUCT:FORMAT:PLACEMENT:CREATIVE:INTERACTION_TYPE`.
- Replaced the stale model-comparison sample statistics in the governance page with the values the shipped `amc_mta_model_comparison_summary.csv` actually contains.
- Fixed a dead `modules/amc_mta/` attribution path in the budget calculation page and a stale `amc_mta/` submission reference in the module page.
- Added the missing `test_mta_sim_generator_adapter.py` suite to the test inventory, reconciling the table with its stated 284-test total.
- Expanded the strategy Campaign output example to include every key the generator always emits, including `bridge_summary`, `minimum_required_daily_budget`, `recommended_ad_groups`, and the full `count_rationale`, and documented the full-precision float storage.
- Corrected the documented inputs, outputs, dependencies, and verification notes for the hierarchy validator, budget recommender, dataloader, evaluation, output contract, model registry, attribution model interface, DNN model, and both native model pages.
- Documented `script/export_drawio_diagrams.mjs`, previously absent from both the script README and the site, and gave all three documentation-tooling helpers a home under `docs/en/environment/`.
- Removed the orphaned `modules/mta_attribution/run_pipeline.py`, a tracked duplicate of `script/run_pipeline.py` that nothing imported and that contradicted the rule centralizing commands in `/script`.
- Restored the canonical `initial_budget_recommendation.json`, which was missing from the working tree and is required by `--check-output` and the strategy tests.
- Consolidated versions 0.1 through 0.4 into one archived page to stay within the ten-page version-log limit.
