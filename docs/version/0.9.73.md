# Version 0.9.73

Date: 2026-09-18

## Changes

- Fixed the dead end on **Compute the strategy**. A disabled control reported only that the step could not be completed, which named a fault and offered nothing. The campaign selection is now an `input` step of its own: it tells the reader to pick a campaign and confirm its marketplace, watches the rendered controls, and advances by itself the moment the selection is valid — which is also the moment **Recompute strategy** enables. The reader now reaches that button only when it works.
- Added the `input` step kind and an exported `READINESS` map of checks. A readiness check reads the rendered controls rather than application state, because the overlay sits outside every view; what the reader can see is exactly what it checks. Like an action step, an input step carries no Continue button and cannot be skipped with the arrow key.
- Every action step now carries a `recover.hint` naming what its control needs, shown in place of the fault. Where the missing setup is a known number of steps back, **Set that up first** returns there. While a step is blocked the overlay keeps re-checking the control, so a prerequisite satisfied without leaving the step clears the message and re-arms the click. Steps the deployment genuinely cannot offer remain `optional` and keep **Skip this step**.
- Added `DEMO_NOTICE`, rendered under every step marked `demo`, stating that the data is for demonstration only and that the KFC example is a recognisable label on simulated records rather than real advertising data. It appears on the steps where the reader is looking at or choosing real records, rather than in a footnote elsewhere.
- Added a data-source step pointing at the Settings **Schema setup** group for a deployment with no readable schema, so the tutorial teaches the existing way to build one instead of carrying a bootstrap of its own.

## Verification

191 dashboard tests passed, including a new one asserting that no dead-end message remains, that every action step carries a remedy or a skip, that every input step names a readiness check that exists in `READINESS`, and that the demonstration notice is defined and rendered. The production build succeeded and the rebuilt Docker stack serves the notice, the recovery control, the readiness check, and the self-advancing hint.
