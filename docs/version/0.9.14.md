# Version 0.9.14

Date: 2026-08-17

## Changes

- Added `useFolderTitleFromIndexFile: true` to every sidebar scan block in `docs/.vitepress/config.mts`. Nested folders with their own `index.md` — `en/attribution/standardized-interface/`, `en/introduction/environment/`, and the three `en/research/` subfolders — previously showed the raw, hyphenated directory name in the sidebar (for example "standardized-interface") instead of that folder's own `title` frontmatter ("Standardized MTA Interface"), because `useFolderLinkFromIndexFile` controls the folder's link target but not its displayed text. Audited every nested subfolder under `docs/en/` and confirmed each one already carries a proper `title` field, so this single config change fixes all of them.
- Reversed the version-log compaction policy at the owner's direction: it must not auto-compact older patches going forward. Expanded the archived `0.1-0.9.4.md` back into one full page per patch — `0.1` through `0.9`, then `0.9.1` through `0.9.4` — recovering the same material each version originally documented.
- Restructured `docs/version/` into one collapsed-by-default folder per minor version (`0.9/`, `0.8/`, ... `0.1/`), each folder's own `index.md` holding that minor version's base release and, for `0.9/`, its later patches `0.9.1` through `0.9.10`. The four most recent patches, `0.9.11` through `0.9.14`, stay as flat pages at the top of `docs/version/`, outside any folder.
- Fixed the sidebar's version sort: every page had tied at `order: 1`, so `sortMenusByFrontmatterOrder` fell back to comparing filenames as strings, and `"0.9.10"` sorts before `"0.9.13"` alphabetically even though it is the older patch. Assigned every version page, and every minor-version folder's index page, a distinct order value that sorts newest first.
- Replaced the ten-page consolidation rule in `AGENTS.md` with the folder-based, no-compaction policy above, so future patches follow the same structure instead of re-compacting history.
- Added a **Planned** section to `docs/version/index.md` recording the owner's proposal to consolidate a minimal, class-based set of data structures across `modules/mta_attribution`, `modules/mta_standard`, `modules/mta_strategy_recommendation`, `modules/mta_strategy_evaluation`, and the dashboard's database schema; to move `dashboard/config.py` and `dashboard/models.py` into `modules/mta_standard` and `docs/en/dashboard/database-import.md` into `docs/en/attribution/standardized-interface/` to match; and to implement a full runnable optimizer module on the consolidated structures. None of this has started — it is recorded so the next session picks it up rather than losing the proposal. Added the matching goal to the work log at [`docs/worklog/ZheyuanWu.md`](../worklog/ZheyuanWu.md).

## Verification

- Inspected the built `docs/.vitepress/dist/version/index.html`: the sidebar lists `0.9.14, 0.9.13, 0.9.12, 0.9.11`, then the collapsed `0.9` folder (containing `0.9.10` down to `0.9.1`, newest first), then `0.8` down to `0.1`, all in correct descending order.
- Inspected the built `docs/.vitepress/dist/en/attribution/standardized-interface/index.html`: the sidebar group header now reads "Standardized MTA Interface" instead of "standardized-interface".
