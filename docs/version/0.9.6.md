# Version 0.9.6

Date: 2026-08-13

## Changes

### The dashboard

- Added `dashboard/`, a locally deployable presentation layer over the artifacts the pipeline already produces. Six views mirror the reference design in `external/UI_design`: Command Center, Budget Manager, Campaigns, Campaign Optimizer, Optimization Log, and Knowledge Base.
- Established the rule the module is built around: **the dashboard never computes an attribution share or a budget figure**, it reads them. A presentation layer that recomputed a pipeline number would become a second, divergent implementation of it. The single derived value, the Campaign Optimizer's implied budget shift, is labelled as a restatement and is withheld entirely when the Outcome's verdict is UNRELIABLE.
- Declared Streamlit, Plotly, pandas, SQLAlchemy, and the PostgreSQL driver as the optional `dashboard` extra rather than as project dependencies, so `modules/` keeps its standard-library-only property and a reader can still reproduce every published number with no installation step.
- Two of the reference design's views had no backing data. Rather than ship placeholder content, each was pointed at the real record answering the same question: Optimization Log reports run provenance and states that the optimisation stage has not run, and Knowledge Base is populated from the data in use so it cannot drift from the charts beside it.

### Dual data source

- Added the `DATABASE=true/false` switch. False reads the committed CSV and JSON artifacts, which needs no database and is what a cloud demonstration uses; true reads the PostgreSQL mirror. `sample.env` is the tracked template and `.env` is git-ignored.
- Made `dashboard/data_source.py` the only module that knows which mode is active. Every loader returns the same columns, dtypes, and values in both modes, so no view branches on the data source.
- Fixed three real differences that would otherwise have broken views on switching source: PostgreSQL folds unquoted identifiers to lowercase, so the platform's camelCase names were renamed to `snake_case` in both modes; the pipeline writes reliability flags as the strings `true` and `false`, and the non-empty string `"false"` is truthy in Python, so they are parsed to real booleans; a date is a string from a file and a `date` from the database, and pandas infers a different unit for each, so both are parsed and pinned.
- Added `script/verify_source_parity.py`, which probes both modes in separate subprocesses — `config.use_database()` is `lru_cache`d, so one process cannot hold both — and exits non-zero naming any field that differs.

### PostgreSQL mirror

- Added `dashboard/models.py`, the single definition of an eighteen-class schema in four layers: entity, history, model output, and strategy. Every run-scoped table carries a foreign key to its run, so two report windows coexist rather than overwrite, and each unique constraint is scoped by run so a re-import is a conflict rather than a silent duplicate.
- Added `script/import_to_database.py`. It refuses to overwrite a populated database without `--replace`, supports `--dry-run` without opening a connection, and runs in one transaction so a failure part-way leaves the database untouched.
- Corrected the description-row filter to match the exact first-cell marker. The earlier heuristic tested for the absence of digits and silently discarded a real touchpoint row from the files that carry no description row.

### Navigation rail and settings module

- Replaced the sidebar select list with the reference design's rail: grouped section labels over stacked icon buttons, with the active item filled. Streamlit has no icon-button widget, so each item is a real button carrying its icon as a background image; an inline `<svg>` cannot live in a button label, and a marker element drawn above the button is unreachable from it because Streamlit wraps every element in its own container.
- Added `dashboard/settings.py`, pinned to the foot of the rail and ruled off from the view navigation so dashboard plumbing never reads as a seventh place to navigate to. It edits the database credentials in `.env` and streams a bounded log of the SQL and connection activity.
- Established that no credential reaches a tracked file, the page, or the log. `.env` is git-ignored, `sample.env` holds no real value, and the password is rendered only through `DatabaseSettings.safe_summary()`, which omits it by construction. `write_env()` rewrites the file in place, preserving comments and unrelated keys, so one key cannot end up with two values and the winner decided by read order.
- Fixed a chart defect the rail work surfaced: `style_figure()` styled a figure title without setting its text, which left Plotly drawing the literal word `undefined` above every plot.

### Documentation restructure

- Merged the twenty-two implementation pages into the conceptual pages that own them, as a `## Source Files` section rather than an `implementation/` subdirectory, and rewrote the corresponding rule in `AGENTS.md` to state that convention: the contract lives beside the behavior it specifies, each file's coverage is declared in the page's `source_files` frontmatter, and a page whose subject has no Python file simply has no such section.
- Renamed `docs/en/strategy/` and `docs/zh/strategy/` to `strategy_recommendation/` to match the module name, and moved the module-ownership diagrams to `docs/en/reference/`.
- Added `docs/en/dashboard/index.md` and `docs/en/datasets/dashboard-data-model.md`, the latter specifying all eighteen data classes under third-level headings.
- Consolidated versions 0.1 through 0.6 into one archived page to stay within the ten-page version-log limit.

## Verification

- `uv run --extra dashboard python -X utf8 -B -m unittest discover -s dashboard/tests -p "test_*.py"` passes at 10 tests, covering app start, every view rendering, the loader column contract, the boolean parsing, and the settings module's `.env` handling against a temporary file.
- `uv run --extra dashboard python script/verify_source_parity.py` reports parity across 10 loaders against the populated instance.
- `npm run build` in `docs/` completes with no dead links after the section rename and the implementation-page merge.
- The rail, both settings tabs, the active-state transition, and the log capture were verified in a real browser; the log captured live SQLAlchemy statements with no credential in the stream.
