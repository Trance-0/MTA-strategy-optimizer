# Version 0.9.36

Date: 2026-09-01

## Changes

- Added Data Generator immediately after Command Center. Guided fields and a
  JSON editor share one self-contained configuration; the backend invokes the
  pinned MTA-SIM package asynchronously, returns two previews capped at 20
  rows, exposes two allow-listed CSV downloads, and performs optional
  PostgreSQL export only on the backend with write-only credentials.

- Made schema state actionable. Selecting any dashboard-ready schema opens a
  confirmation and probes the target before reloading every view; failure
  restores the prior schema. A database-load error now offers safe backend-
  declared select, derive, or initialize actions without replacement. Schema
  setup permission is independent of protected credentials.

- Flattened the navigation rail into one column, moved Reload data into
  Settings, removed snapshot-derived Knowledge Base content, and added
  keyboard-accessible definitions with precise English documentation links to
  shared metric, key/value, and table labels.

- Tightened credential transport: remote PostgreSQL export requires HTTPS,
  localhost is the only HTTP exception, and a forwarded protocol is trusted
  only when one managed proxy hop is explicitly enabled.

## Verification

- All 100 backend tests and 45 dashboard tests pass. Ruff passes for every
  touched Python file. The production dashboard and VitePress documentation
  builds complete; the existing Plotly chunk-size warning remains unchanged.

- A real browser generated the baseline toy dataset, rendered path and
  performance previews with 6 and 12 rows, exposed exactly two CSV downloads,
  opened the JSON editor, and showed no console errors.

- The same browser confirmed `public` to `mta_us`, loaded the target's actual
  29-table snapshot, rendered 10 Campaign rows, opened term help with its exact
  documentation link, and showed only the disconnected Knowledge Base notice.

- Direct `curl --noproxy "*"` probes found the deployed 0.9.35 service healthy
  for settings, snapshot, and research history, but `/api/data-generator`
  remains 404 until this full-stack release is deployed.

## Database upgrade plan

The existing [database migrations and continuous deployment
plan](/en/introduction/backend/database-migrations) remains authoritative:
baseline the untracked schemas with Alembic, use expand-contract revisions,
run an advisory-locked pre-deploy migration Job, test upgrades from the
previous release, gate application rollout on revision compatibility, and use
forward repair or provider recovery rather than automatic down-migrations.
