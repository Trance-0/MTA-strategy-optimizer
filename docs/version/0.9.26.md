# Version 0.9.26

Date: 2026-08-20

## Changes

- Added `dashboard/server/master_data.js`, which derives the master-data catalogue — Ad Providers, Products, Campaigns, Ad Groups, touchpoints, product economics, and Campaign-Product links — from the committed Amazon Ads report, entity bridge, and strategy request rather than from an optional `MTA_SIM_DATA_DIR` sidecar. Every entity section on Budget Manager previously stood empty in the default and published deployments because that sidecar is the only thing that had ever filled them; they now describe the account from files the repository already tracks. Derivation was chosen over committing a second catalogue file because a tracked catalogue beside the reports can drift from them, while one read out of them cannot.
- Reported four fields from observation instead of computing them from mismatched denominators. A touchpoint's impressions and clicks arrive as separate per-interaction rows sharing no denominator, so dividing one by the other produced click-through rates between 0.98 and 1.15; `click_through_rate` is now `null` with `observed_impressions`, `observed_clicks`, and `observed_cost` reported in its place. Four touchpoints bill CPC on clicks and CPM on impressions at once, so cost is accumulated per billing type and the billing type is reported as `CPC + CPM`. A rate is reported only where both its cost and its denominator are above zero, so a touchpoint whose impression rows carry no cost no longer shows a CPM of exactly zero. Unit COGS and contribution margin stay `null` rather than becoming zero, since the reports do not carry them.
- Rebuilt the narrow-viewport navigation. Below `1024px` the sidebar rail had kept its full vertical layout at 100% width, pushing the page content below the fold; it is now a sticky horizontal bar with its label, status detail, log, and links tiers hidden, and below `620px` it drops to icons only. Every nav and foot control carries an `aria-label` and `title`, because the labels those controls are read by are hidden with CSS at that width.
- Revised the dashboard's wording to describe market data rather than a data generator. "Generated history" is Budget history, "Generated observations are read-only" is "Reported performance is read-only", drafts are planned changes, and an empty section reports having no records in the current reporting window instead of naming an environment variable a marketing reader has no way to set. No dashboard string now mentions MTA-SIM, simulation, or synthesis, and a test asserts that across the views, the settings dialog, and the deployment module.
- Moved pipeline-run detail behind a diagnostics preference in `dashboard/src/lib/diagnostics.js`, surfaced as "Show data run diagnostics" in Settings and persisted in `localStorage`. It gates Budget Manager's Data Run Diagnostics section and the Campaigns data-run filter.

## Verification

- 50 dashboard tests pass, three of them new: that no dashboard source presents its data as generated or simulated, that the rail becomes a bar rather than a tall block below the wide breakpoint, and that diagnostics are a preference that is off by default.
- Confirmed the derived catalogue against the committed reports in file mode: 1 Ad Provider, 4 Products, 4 Campaigns, 8 Ad Groups, 13 touchpoints, 4 product economics records, and 16 Campaign-Product links.

## Notes

- The request was to enable the diagnostics view by default. It ships **off** instead: showing pipeline internals to a marketing reader on first open reproduces the same problem as the generated-data wording this version removes. The preference is one toggle in Settings for anyone who wants it on.
