# Version 0.9.17

Date: 2026-08-18

## Changes

- Added `modules/mta_common/src/`: a provider-independent canonical domain model as `@dataclass(frozen=True)` value objects, replacing the `AD_PRODUCT:FORMAT:PLACEMENT:CREATIVE:INTERACTION_TYPE` five-segment string key as the intended ground truth while keeping that key fully supported as a backward-compatible serialization. `provider` is now a first-class field distinct from `ad_product`. Five explicit missingness states (`AVAILABLE`, `NOT_APPLICABLE`, `NOT_PROVIDED`, `UNKNOWN`, `REDACTED`) replace a single collapsed "unspecified" value in the canonical model. `StrategyObjective` and `BudgetUsagePolicy` are declared as two independent enums so a future optimizer can represent all four combinations; no optimizer is implemented.
- Added `Product`/`ProductEconomics`/`CampaignProductLink`, separating business identity from advertising identity, with missing cost-of-goods-sold kept `None` rather than zero-filled, and the Campaign-Product relationship modeled as an explicit many-to-many link rather than a single SKU field on Campaign.
- Added `BudgetObservation` (configured budget and actual spend as independent fields; under-spend is valid) and `OutcomeObservation` (total-observed outcomes kept distinct from organic-baseline and incremental-attributable outcomes; the incremental fields are never fabricated from today's total-observed data).
- Added `AttributionEvidence` as pure historical evidence with no marginal-return, causal-incrementality, optimal-budget, or product-contribution-profit claim, and `DataLineage` for provenance tracking.
- Added `CampaignEpisode`/`EvaluationEpisode`, composing decision-time, observed-after-treatment, and (for evaluation only, via composition rather than inheritance) simulator ground-truth records, with an automated `assert_no_ground_truth_fields` isolation check.
- Added `SimilarityReference` in a separate `presentation` namespace, structurally unreachable from every core, model-facing class; proven by four independent isolation tests.
- Added `modules/mta_common/src/legacy_adapters.py`, the only module that imports from `modules.mta_attribution` or `modules.mta_standard`, bridging today's five/four-segment touchpoint keys, `AttributionResult`, `TouchpointSpend`, `StandardAttributionRow`, `strategy_request.json`, and `initial_budget_recommendation.json` into the canonical model, plus a reverse `touchpoint_to_five_segment_key` projection so existing attribution algorithms do not need to be rewritten. While implementing this, found and fixed a real gap: `outcome.py`'s docstring claimed `legacy_adapters.py` populated `OutcomeObservation.total_units`/`total_revenue`, but no such function existed; added `outcome_observation_from_touchpoint_spend` to close it.
- Added `modules/mta_common/tests/` (9 files, 96 tests), including a new `test_campaign.py` closing a coverage gap found this session: `Campaign`/`AdGroup` had no dedicated validation tests before.
- Added `docs/en/introduction/data-models/` (27 pages: one hub `index.md` plus 26 individual class pages, one per canonical class, kebab-case filenames matching class names), linked from `docs/en/introduction/index.md`'s reading order and entry-points table. Added a `COGS`/`Contribution Margin` glossary section to `docs/en/reference/definitions.md`.
- Nothing outside `modules/mta_common`'s own test suite imports it yet — this is a foundation laid ahead of integration, not a change to any running pipeline's behavior.
