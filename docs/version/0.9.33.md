# Version 0.9.33

Date: 2026-08-27

## Changes

- Added a **Deployment identity** block at the top of Settings. It shows the
  dashboard project version and full Git commit identifier beside the backend's
  independently detected values, plus the Python and Flask versions running on
  the backend. Every value remains selectable for copying into a deployment
  report.

- Reports **Builds match** only when both project versions and both full commit
  identifiers are known and equal. Unequal values report **Build mismatch**;
  missing build metadata reports **Identity incomplete**; and a static
  dashboard reports **Backend not connected** rather than comparing against
  itself.

- Made the Vue build read `VERSION` and resolve its commit from
  `BUILD_COMMIT`, `GITHUB_SHA`, or the local Git checkout. The backend reads
  the same root version, prefers `PROJECT_COMMIT` and then `GITHUB_SHA`, and
  falls back to the local checkout. Only full 40- or 64-character Git object
  identifiers are accepted; unavailable metadata becomes `unknown`.

- Passed the checkout revision to both local Docker builds and the container
  publishing workflow. The dashboard image bakes it into the browser bundle;
  the backend image exposes it as `PROJECT_COMMIT`. The AppStack image follows
  the same build-argument contract, while `.git` remains outside every Docker
  context and image.

- Updated the dashboard view, client boundary, backend settings, backend setup,
  and deployment specifications before implementing the behavior. Moved
  version `0.9.29` into the `0.9/` history folder so only the latest four patch
  pages remain flat.

## Verification

- Seventy-one backend tests and thirty-one dashboard tests pass, including
  project-version reading, build-commit precedence, backend runtime identity,
  match-state rendering, static-host behavior, and deployment metadata
  propagation.

- Ruff lint and formatting pass for the touched Python files. The Vue
  production build and VitePress documentation build complete, and Git reports
  no whitespace errors.

- The built Vue bundle contains project version `0.9.33` and the full local
  checkout commit used for this pre-commit build. A direct backend settings
  probe returns the same project version and full commit together with detected
  Python and Flask versions.

## Operational Notes

- A local build from a dirty checkout reports the current `HEAD`, because
  uncommitted changes do not have a Git identifier. Published images receive
  the commit that triggered their workflow, so their displayed identity names
  the exact committed source used for deployment.

- `unknown` is intentionally visible and never equals another `unknown` for
  match purposes. Supply `BUILD_COMMIT` when building outside a Git checkout.
