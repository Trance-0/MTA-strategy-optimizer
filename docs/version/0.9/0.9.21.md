# Version 0.9.21

Date: 2026-08-19

## Changes

- Documented the implemented Campaign budget response model and constrained optimizer in a new `docs/en/strategy-recommendation/campaign-budget-optimizer.md`. The page specifies the two-stage saturating fit from configured budget to actual spend and from spend to revenue, the `TARGET_HISTORY`, `POOLED_TRANSFER`, and `INSUFFICIENT_SUPPORT` evidence labels, the shadow-price solver that equalizes marginal expected revenue across unconstrained Campaigns, every structured refusal, the `campaign_strategy.json` field contract, and the `## Source Files` code-level contract for all five files.
- Corrected the pages that still described the optimizer as unimplemented. `strategy-recommendation/index.md` now separates the implemented Campaign-level optimizer from the still-proposed Ad Group-level response model, `reference/module-inventory.md` states the module's real status, and `reference/data-flow.md` gains a Layer 9 for the optimization chain along with its five new file-reference entries.
- Added `loadCampaignStrategy()` to `dashboard/server/data_source.js` and `campaignStrategy` to the snapshot bundle and the client's empty-state object, reusing the existing `cached`/`readJson`/`STRATEGY_OUTPUT_DIR` pattern. The loader is mode-independent by construction: the artifact is written by a research command rather than by the import pipeline, so both modes read the one file and an absent file yields `{}`.
- Replaced the Optimization Log's hard-coded `NOT RUN` fifth stage with the real plan. The view now shows the authorized, allocated, and expected-revenue tiles, one row per Campaign with its budgets, expected revenue, marginal return, evidence label, and extrapolation flag, and names every extrapolated and every pooled Campaign. A refused plan shows its `recommendation_type` and reasons instead of an allocation, and expected revenue is labelled a model estimate rather than a realized uplift.
- Added six Strategy and Optimization definitions the new page depends on: Concavity, Shadow Price of Budget, Budget Response, Extrapolation, and Pooled Transfer, each cross-linked to the existing Response Curve, Marginal Revenue, Attribution Share, and Causal Incrementality entries.
- Taught `script/export_drawio_diagrams.mjs` to skip any `-human.drawio` source and report the count it skipped. A hand-authored diagram is kept beside its agent-authored counterpart, but only the unsuffixed source is rendered, so one page cannot publish two pictures of the same subject with nothing to say which is authoritative. Re-exported all 11 rendered sources, restoring the canonical data-model relationship diagram that the data-models overview embeds.

## Verification

- Passed 476 Python tests: 103 `mta_common`, 98 `mta_standard`, 160 attribution, and 115 strategy, the last including the end-to-end `test_response_pipeline.py` that generates real Multi-Touch Attribution Simulator (MTA-SIM) output and runs the full adapt, aggregate, fit, and optimize chain against it.
- Passed 33 dashboard tests, two of them new: one asserting the snapshot always carries `campaignStrategy` and that a plan claiming optimization is never labelled `INITIAL_SEED`, and one asserting the Optimization Log reads stage 5 from the artifact rather than from a constant.
- Ran `script/generate_campaign_strategy.py` end to end against a freshly generated research snapshot: 40 observations, 2 Campaign models, `is_optimized=true`, with 66.0 of 66.0 authorized budget allocated and the two Campaigns' marginal expected revenue equal to seven decimal places, which is the equal-marginal condition the solver is built on.
- Confirmed the artifact reaches the browser by querying the running dashboard's `GET /api/dashboard` in file mode and reading `OPTIMIZED_CAMPAIGN_BUDGET` with both allocations from the response.
- Built the documentation site and the dashboard production bundle successfully. VitePress fails on a dead link, so the new page's cross-references resolve.

## Notes

- `modules/mta_strategy_recommendation/outputs/campaign_strategy.json` is a generated artifact and remains git-ignored, consistent with the initializer's own output rule.
- Every rendered SVG changed in this patch, because a newer Draw.io build compresses embedded images more and places text a fraction of a pixel differently. Canvas dimensions, embedded sources, and image counts are unchanged; the diagrams themselves were not redrawn.
