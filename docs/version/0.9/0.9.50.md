# Version 0.9.50

Date: 2026-09-09

## Changes

- Database attribution preparation recognizes a simulator path report's next-day
  end boundary only when its saved run configuration proves the actual inclusive
  performance window. It validates the complete input pair before publishing;
  missing dates, duplicate daily keys, ambiguous provenance and other scope
  mismatches still fail. Existing database rows are never rewritten.
- New scenario derivations infer the inclusive model window from validated daily
  performance and reject source paths outside it. Path aggregates, attribution
  metadata and downstream bridge records receive the same window.
- StageRunner, BackendTasks, OptimizationLog, SchemaRecovery and Settings now use
  one LogViewer. Copy includes retained records, timestamps, task context, exact
  command and truncation notices; Settings copies only filtered records. Browser
  clipboard fallback cleans up even on failure and restores focus. Live output
  follows only its own container while the reader remains near the tail.
- Settings refresh uses server configuration to restore the blue database theme
  without requesting dashboard data. Unknown sources no longer appear as green
  Local files; configuration alone never enables editing. The header separates
  deployment identity from loaded-data permission.

## Verification

- All 154 backend tests passed. Regression cases execute the real attribution
  command function and produce all five artifacts for a full year ending
  2025-12-31 and a single leap day. Invalid input cases preserve existing files.
- The isolated change set passes all 147 dashboard tests and the production
  build. Shared-log tests cover text rendering, complete copy payloads, denied
  clipboard fallback, cleanup, failure feedback and bounded-buffer scrolling.
- The working-tree documentation build passes. The normal dashboard prebuild
  hits an existing Windows directory-rename error; the already-generated
  ontology fixtures were verified before building with
  `npm --ignore-scripts run build`, which also verifies the packaged fixtures.

## Deployment

The failure report came from a deployed `script/run_attribution_models.py`
command. This repository already uses the package-native attribution entry
point. Deploy this patch through the maintained pipeline before retrying the
selected dataset. No production database mutation or deployment was performed.
