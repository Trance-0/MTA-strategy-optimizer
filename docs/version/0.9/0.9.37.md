# Version 0.9.37

Date: 2026-09-02

## Changes

- Replaced shallow hashes with canonical `#/page/section` links. Budget
  Manager, Campaigns, Campaign Optimizer, and Optimization Log tabs now own
  stable URLs; single-panel destinations have explicit default subsections.
  Legacy page-only hashes normalize without adding history, while reader
  navigation adds history and Back and Forward restore the selected tab.

- Replaced the Vue client's mandatory whole-snapshot load with route-owned
  resources. Each subsection declares exactly what it needs; the store merges
  nested research slices, shares concurrent requests, reuses completed
  resources, records failures by resource, and invalidates every client and
  server cache on Reload.

- Added `GET /api/dashboard/resources/<resource>` behind a fixed backend
  registry. Unknown names return a bounded 404 before any loader runs, and no
  browser value becomes a path, table, column, or query. Static builds export
  the same registry as one JSON file per resource and the Pages assembler
  requires the common shell resource.

- Kept the ordered whole snapshot as a compatibility and schema-validation
  assembly, so runtime schema switching still probes the entire selected
  schema before making it active.

## Verification

- All 103 backend tests and 46 dashboard tests pass. Ruff lint and formatting,
  Python compilation, production and static Vue builds, and the VitePress
  documentation build complete. The existing Plotly and documentation chunk
  size warnings remain unchanged.

- A real browser opened `#/campaigns/paths` directly and requested only
  `shell`, `path-report`, and Settings. Moving to Campaign Bridge requested
  only `entity-bridge`; Back and Forward restored both tabs; revisiting Paths
  made no request. The legacy `#budget` link normalized to
  `#/budget/overview`, Providers requested only its missing research resource,
  and no console error was recorded.
