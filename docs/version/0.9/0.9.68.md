# Version 0.9.68

Date: 2026-09-18

## Changes

- Grouped the navigation rail into four registered sections (`NAV_GROUPS` in `dashboard/src/pages.js`) and rebuilt `SidebarNav.vue` to render them. Below the `1024px` bar breakpoint a section holding more than one page now collapses into a labelled disclosure with `aria-expanded`, `aria-controls`, and a rotating chevron, while a single-page section such as Settings stays a plain item. The stylesheet already carried the complete bar-disclosure rules; no markup had ever used them, so the rail flattened into one undifferentiated scrolling strip.
- At most one disclosure is open: choosing a destination, navigating by any other route, and `Escape` all close it, and a closed section containing the active page keeps the active fill.
- Added `dashboard/src/components/GuidedTour.vue`, offered as an option row in a new **Getting started** group at the top of Settings General. It walks ten ordered steps — the summary, choosing a source, generating or importing, attribution, optimization and its refusal case, evaluation, the provenance log, the vocabulary, and Settings — navigating through the location hash so it drives the real application. It explains only: it starts no stage, writes no setting, and changes no dataset selection. Progress is kept under `mta.tutorialStep` so an interrupted tour offers to resume.

## Verification

188 dashboard tests passed, including new assertions that `NAV_GROUPS` partitions `PAGE_KEYS` exactly, that the disclosure markup and its closing behavior are present, and that every tour step names a registered page and subsection while referencing no job, settings, reload, or dataset-selection call. The production build succeeded and the rebuilt Docker stack serves the rail markup and bar rules in the main bundle and the tour in the lazy Settings chunk.
