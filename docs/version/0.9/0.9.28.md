# Version 0.9.28

Date: 2026-08-25

## Changes

- Built `modules/mta_strategy_evaluation/` around a shared `StrategyOutput` decision contract. The deterministic budget seed and Campaign response optimizer now project into the same dataclasses without changing either producer, with allocation conservation derived from the decision rather than stored beside it. `StrategyEvaluationEpisode` composes the decision with ordinary `CampaignEpisode` observations and keeps strategy ground truth separate, following the same model-facing isolation as attribution evaluation.
- Implemented the three evaluation layers: contract and conservation checks without observations, comparison with equal-split and observed-budget baselines when every allocated Campaign is observed, and an explicit not-run ground-truth result because Multi-Touch Attribution Simulator (MTA-SIM) publishes attribution truth rather than a true optimal strategy allocation. The committed seed and optimizer describe disjoint Campaign sets, so the seed names its four unobserved Campaigns instead of receiving fabricated zero scores.
- Moved Yi Liu's contributor-owned scripts, documentation, data, and recorded results byte-for-byte from `docs/en/strategy-evaluation/asin-gmv-nn/` to `modules/mta_strategy_evaluation/contrib/mlp/`, reserved `contrib/classical/`, and added the project-owned `asin_gmv_nn_adapter.py`. The adapter pivots canonical Campaign response observations to the contributor's marketplace-day grain, imports the trainer in place, and carries the contributor's negative held-out coefficient of determination (R-squared) as a blocking caveat.
- Named each `contrib/` folder after the kind of model it holds rather than after its author, and recorded that rule in the root instructions and on the contributed-models page. A person's name is the wrong identifier for a path that code, tests, documentation, and the artifact schema all cite, because a contribution can change hands; authorship stays in `docs/worklog/` and in Git history. The report field `contributor` became `contrib_folder` for the same reason, and the duplicate copy of the contribution under `docs/zh/strategy-evaluation/asin-gmv-nn/` was deleted so no contributed code remains under `docs/`.
- Added `script/evaluate_strategies.py` as a train-on-demand pipeline command. It projects both strategy artifacts, runs every available layer, optionally fits the contributed model through the `strategy-evaluation` dependency extra, and writes one deterministic ignored `strategy_evaluation.json`; it stores no checkpoint, accepts no uploaded binary, and writes nothing into a contributor folder.
- Made strategy evaluation the third dashboard-runnable model stage in `backend/services/jobs.py`, with five progress phases and no research-snapshot requirement because the command falls back to `campaign_strategy.json` observations. Added the `strategyEvaluation` dashboard snapshot key and an empty-object pre-run state, while keeping the current view honest that it can start the stage but does not yet visualize the report.
- Replaced the maintained runtime path behind the Vue dashboard with the Flask `backend/` service and Python repositories, retained the former Node modules only as JavaScript parity fixtures, replaced the JavaScript snapshot exporter with `script/export_dashboard_snapshot.py`, and replaced the former deploy worker bundle with the AppStack deployment contract. English documentation remains the published language while preserved Chinese routes resolve to the construction placeholder.
- Updated the glossary, module inventory, development commands, dashboard and backend specifications, root instructions, and worktree ignore rules to describe the implemented module and its generated artifacts.
- Corrected stale status claims left by earlier patches: the introduction called the strategy optimizer unimplemented, the progress page listed the delivered response model and constrained optimizer as outstanding todos and stated `is_optimized=false` for a module whose optimizer now reports true, the canonical data-model page said no `EvaluationEpisode` consumer existed, and both contributors' Scope lines described the evaluation module as an empty placeholder. Also fixed a contributed-model page claiming a 19-column design matrix where canonical mode builds 18, because the market indicator is one-hot encoded over the marketplaces actually present.

## Notes

- The current optimizer observations cover `CAMPAIGN-DISPLAY` and `CAMPAIGN-SEARCH`; the deterministic seed allocates to `C_DEMO_SP`, `C_DEMO_SB`, `C_DEMO_SD`, and `C_DEMO_DSP`. A research snapshot that observes the seed Campaigns is required before its baseline comparison can run.
- The contributed model is research evidence, not a decision model: its committed held-out R-squared is negative, and the current project panel is below the minimum size for a meaningful held-out fit.
- No checkpoint upload or download endpoint was added. Training on demand avoids committing generated binary weights and avoids a deserialization security surface.
