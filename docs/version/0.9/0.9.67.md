# Version 0.9.67

Date: 2026-09-18

## Changes

- `deploy/docker/Dockerfile.api` now creates `/pipeline-output` owned by the runtime user before `USER` drops privileges. Docker initializes a fresh named volume from the image directory's ownership, so the previous image left the volume root-owned, every write probe from uid 10001 failed, and all three pipeline stages — and the model log tabs behind them — reported "PIPELINE_OUTPUT_DIR must name a writable runtime directory".
- Added `pipeline_output_remedy()` in `backend/config.py` and routed the stage-unavailable, start-refusal, artifact, dataset-preparation, workbench-storage, and dataset-registry messages through it. The message now names the concrete configured path, tells the operator to grant the service user write permission or repoint `PIPELINE_OUTPUT_DIR`, and names the `docker volume rm marketing-roi-analysis-pipeline-output` remedy for the stale-volume case.
- Specified the actionable-message requirement on the backend operations page.

## Verification

203 backend tests passed. The rebuilt Docker stack (after removing the stale volume) reports all three stages available; attribution, optimization, and evaluation each ran from the dashboard job API with streamed logs and exit code 0, writing their artifacts under `/pipeline-output`. The Optimization Log tabs now show run state, duration, command, and streamed output instead of the unavailable notice.
