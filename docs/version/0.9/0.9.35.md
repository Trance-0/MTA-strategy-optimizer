# Version 0.9.35

Date: 2026-09-01

## Changes

- Split `history`, `delivery`, and `touchpointObservations` from the core
  dashboard snapshot into `GET /api/dashboard/research-history`. Campaigns and
  Budget Manager request that shared payload on entry; unrelated views no
  longer download or parse it. Both requests report delayed byte progress, and
  static export writes equivalent core and research files.

- Made Campaigns safe at the supported 100,000-row history size. Chart extrema
  scan iteratively instead of spreading an array into `Math.max()`, avoiding
  the JavaScript argument limit. Loading and failure states remain visible,
  and a successful request is shared across Campaigns and Budget Manager.

- Exposed the active and readable PostgreSQL schemas in protected Settings.
  The inspection dropdown cannot change `PG_SCHEMA`; it names the active schema,
  capability, table count, and the honest database-structure status **not
  tracked**. Added a phased database migration and continuous deployment plan
  for an Alembic baseline, expand-contract changes, advisory-locked pre-deploy
  jobs, previous-release upgrades, compatibility gates, and forward recovery.

- Replaced client-invented model date controls with server-issued dataset
  choices. The backend materializes the selected attribution, optimization, or
  evaluation scope, validates it again before spawning, and invokes the current
  Python interpreter directly. Container runtimes install the strategy
  evaluation dependencies needed by that interpreter and no longer require a
  writable uv cache or home directory.

## Verification

- Direct requests bypassing the system proxy measured the deployed core at
  51,725,842 bytes and confirmed its backend returned five schemas while the
  served client bundle contained none of the schema UI text. The patched core
  against the same configured database is 810,767 bytes; the lazy history is
  50,923,187 bytes and carries 100,000 history plus 7,000 delivery rows.

- The patched Campaigns page loaded all 100,000 observations in a real browser
  with populated filters, metrics, chart, and paged rows and no console error.
  Protected Settings rendered all five schemas, marked `public` active, and
  labelled every database structure **not tracked**.

- All 85 backend tests, 577 module tests, and 39 dashboard tests pass. The Vue
  production build and Python compilation complete; the module suite was run
  with Python's UTF-8 mode so its text fixtures decode consistently on Windows.

## Deployment note

The running service reports backend `0.9.34` but serves a client asset without
the 0.9.31–0.9.34 Settings features. Deploy this commit as one full-stack image
and confirm Settings reports matching version and commit identities before
accepting the rollout. This commit does not perform a database migration; it
adds visibility and the implementation plan for introducing one safely.
