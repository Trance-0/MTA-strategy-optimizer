# Version 0.9.34

Date: 2026-08-28

## Changes

- Separated `PIPELINE_RUNS_ENABLED` from
  `DASHBOARD_CONFIG_READ_ONLY`. A deployment may protect its credentials and
  logging configuration while still advertising and executing model stages;
  file mode and an explicitly disabled runner remain refused with distinct,
  actionable messages.

- Made deployed job state coherent by running one pod and one Gunicorn worker.
  AppStack uses a `Recreate` rollout, a read-only root filesystem, and a
  writable ephemeral `/pipeline-output`; the two-container stack uses the same
  single-worker contract with a named output volume. A runtime preparation or
  permission failure becomes a retained failed job rather than an uncaught
  server error.

- Made runtime results visible without rewriting the image or importing them
  into PostgreSQL. Attribution switches only after its complete five-file set
  exists; the optimized strategy and evaluation switch after their named JSON
  artifact exists. Until then, database or image artifacts remain the
  fallback.

- Parsed native simulator uploads before attribution. Daily path windows are
  partitioned to the marketplace of the advertiser in the selected database
  schema, aggregated into one report scope, and paired with a matching
  performance input. Native rows restore interaction and billing fields from
  their verified five-segment touchpoint. Submitted date filters are refused
  for these already-produced paths rather than silently ignored.

- Fixed research-scale optimization and evaluation. Distinct budget
  interventions assigned to one Campaign and day remain separate experiment
  arms, while copies of one intervention still must agree on their decision
  metadata. Optimization and evaluation receive the selected marketplace, and
  evaluation additionally matches each strategy to observations with the same
  marketplace and currency.

- Replaced the Willow Sakura full-page `iframe` with native Vue widgets in the
  strategy-evaluation tab. All four budgets, marketplace, calendar values,
  placement and creative structure inputs, the Extended-27 network prediction,
  ten-percent comparison, difference, and held-out metrics are interactive in
  the dashboard while remaining isolated from production recommendations.

- All 658 Python tests and all 36 dashboard tests pass. Ruff lint and format

## Operational Notes

- A multi-marketplace simulator upload is never merged across currencies or
  resolved by first-row order. The selected PostgreSQL schema must identify
  exactly one advertiser marketplace present in both uploaded reports.

- AppStack runtime results last for the pod's lifetime and reset when the pod
  is replaced. Docker runtime results last until its named volume is removed.
  Both choices are deliberate deployment state, not committed build output.
