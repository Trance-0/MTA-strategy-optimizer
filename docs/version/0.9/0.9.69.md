# Version 0.9.69

Date: 2026-09-18

## Changes

- Removed the `NAV_GROUPS` rail sections added in 0.9.68, along with every group container, group label, and per-section disclosure in `SidebarNav.vue` and `style.css`. Splitting eight destinations across four menus made the reader open two of them before finding a page; the rail is the flat `PAGE_KEYS` order again, with no grouping of any kind.
- Below the `1024px` breakpoint the whole list now collapses behind a single menu button rather than a row of section triggers. The button names the page the reader is on, carries `aria-expanded` and `aria-controls`, and drops the same flat list over the content within a bounded scrolling height. The bar no longer wraps, which is what previously let it grow back into a tall block.
- Item labels now survive at every width. The previous rule dropped them to icons only below `620px`, which is wrong once the destinations live in a dropped list: a list has the width for its labels and is unreadable without them. The narrowest breakpoint gives up the brand padding and status label instead.

## Verification

188 dashboard tests passed, with the grouping assertions replaced by ones requiring the flat list, the single menu trigger and its closing behavior, and the absence of every `.nav-group` and `.nav-label` rule. The production build succeeded and the rebuilt Docker stack serves `nav-menu-trigger` and `.nav.open` with no group markup or rules remaining in either bundle.
