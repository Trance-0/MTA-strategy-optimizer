# Version 0.9.49

Date: 2026-09-08

## Changes

- Made an option one row everywhere: its name and helper sentence on the left,
  the control that changes it on the right. Settings was rebuilt as titled
  `.setting-group` sections with a short sentence under each option naming what
  it changes and what the alternative does, held back for the options whose
  label already says everything — the standard PostgreSQL connection
  parameters and the filters that name the column they filter.
- Converted the four views that still laid out their own options: the Data
  Generator's variant and preset pair, `MasterObjectForm.vue`, the guided
  generator configuration editor, and `WillowGmvForecast.vue`. Each now uses
  the shared `.setting-group`, `.setting-row`, `.setting-label`, and
  `.setting-control` primitives instead of a grid private to that file.
- Deleted the duplicate row shapes those conversions made redundant —
  `.form-row`, `.form-grid` with its `.span-2` cell, and the Willow field grid
  — and removed `GeneratorConfigEditor.vue`'s `<style scoped>` block, the last
  component-private stylesheet in the client. It invented `--ink`, `--panel`,
  and `--accent`, which `theme.js` never writes, so a deployment's accent never
  reached the forty labels it stacked above their controls.
- Moved every pair of opposed action buttons onto one side. A card's actions
  now sit in a left-aligned `.rec-actions` bar below the title rather than
  opposite it, and the Campaigns window buttons replaced two `&nbsp;` spacer
  labels — a `<label>` wrapping no control is a defect a screen reader reports,
  not a layout device.
- Recorded the rule as a `## Dashboard interface layout` section in `AGENTS.md`
  and specified it in [Visual Contract](/en/dashboard/views/visual-contract#option-rows),
  including the boundary that keeps `.field` for the filter toolbars, the one
  documented exception for the weekly multiplier axis, and the narrow-layout
  stacking below 760 pixels.

## Verification

- `npm --prefix dashboard test` passes 146 tests, including two new contract
  tests: one asserting that all six option-bearing components use the row
  classes, that no second row primitive and no component stylesheet remain, and
  that no invented theme token is read; one asserting the action bar has no
  `justify-content` rule to flip and that no spacer label returned.
- The new tests were confirmed non-vacuous by temporarily restoring
  `.form-row` to `style.css`, which failed the first test, and by removing the
  restoration before the change set was assembled.
- The production Vue build succeeds with only the existing chunk-size warning,
  and the five documentation pages that own these components were updated in
  this change set rather than after it.

## Limits

The weekly multiplier grid keeps its label above each control, because seven
day-of-week values read as one axis rather than seven independent options; the
exception is stated in the visual contract instead of being left to the reader.
`.field` remains a separate stacked shape for filter toolbars, so the two
layouts still coexist by design. The conversions were verified through the
source-text tests and the build; there is no browser rendering test in the
suite.
