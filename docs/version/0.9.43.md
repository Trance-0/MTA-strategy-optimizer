# Version 0.9.43

Date: 2026-09-04

## Changes

- Updated the Dashboard client image stage to copy the root Ontology Review
  importer before the existing Dashboard copy and production build steps.
  The Dashboard copy already supplies the tracked exact-six fixture input, so
  the ordinary prebuild can materialize and verify its five public payloads
  without widening the build context or changing runtime mode.

- Restored Touchpoint vocabulary, Rules, Entities, and Data sources as
  route-controlled, snapshot-backed operational references beside the existing
  canonical Ontology Review. The restored panels only group and format fields
  already delivered by the Dashboard; they do not define a backend ontology or
  recompute attribution, budget, strategy, or evaluation results.

- Extended the existing read-only `budget` resource projection with
  `candidatePool`, so the Entities route receives eligible-candidate counts
  through the same lazy-loading path as `strategyRequest`.

- Documented the clean repository-root Docker context contract. This patch
  does not change R5 fixture bytes, review meaning, model behavior, strategy
  algorithms, or evaluation algorithms.

## Verification

- All 96/96 Dashboard tests and all 10 backend snapshot tests pass. The normal
  Dashboard build, the equivalent static export/build sequence, the VitePress
  documentation build, and final Pages assembly pass; all published outputs
  revalidate the five canonical Ontology Review fixtures.

- The direct `npm run build:static` wrapper is blocked before project execution
  on this host because Windows Application Control rejects `_socket` in uv's
  default Python 3.12 runtime. Running its same export step in an isolated
  system-Python 3.14 environment, followed by the same Vite static build and
  fixture verification, passes.

- Docker Desktop was not running on the verification host, so an actual image
  layer build remains a release-environment check rather than a local claim.
