# Version 0.9.45

Date: 2026-09-06

## Changes

- Integrated the saved Settings page and history-window changes with the current
  main revision. Settings now has deep links and remains reachable when dashboard
  data fails. History defaults to the latest 90 days, validates calendar dates,
  queries bounded database rows, and ignores stale responses after a range change.
- Deferred Trance-0 view and Plotly loading, avoided deep observation proxies,
  bounded chart marks with density grids, parsed streamed frames linearly, and
  added stable table sorting. The local production application's entry script is
  approximately 56.6 kilobytes, down from approximately 257.2 kilobytes; Plotly
  remains a separate large dependency fetched only when a chart mounts.
- Added compact specification search and a scoped source/test ownership gate,
  organized long attribution and shared dashboard contracts by topic, and
  documented verification scope, cases, commands and limitations. Existing
  attribution URLs and contributor-owned dashboard passages remain available.
- Added release-input validation for the pinned generator and materialized Gitea
  snapshot provenance. Incomplete source-only clones skip only the real-generator
  test; release checks reject missing inputs before testing. Completed the
  AppStack client's existing build inputs and excluded locally generated public
  data from Docker contexts to avoid overlay directory replacement failures.

- Replaced the partial Data Generator form with a Guided/JavaScript Object
  Notation (JSON) editor for the complete reviewed configuration. Guided and
  JSON editing retain unknown fields, provenance, null, zero, and false values;
  the editor validates visible fields, preserves ordered touchpoint and path
  references, and requires confirmation before discarding an edit for another
  preset or variant.

- Added an authoritative, side-effect-free preflight endpoint. It returns
  bounded field and section issues, invokes the pinned Multi-Touch Attribution
  Simulator (MTA-SIM) loader for final validation, and is reused before a run
  allocates an identifier, directory, retained state, or background operation.

- Bound accepted preflight and run-poll responses to the exact current
  configuration and opaque run token. Late responses cannot enable a changed
  configuration or replace current feedback. Static deployments explain the
  full-stack requirement and refuse generator operations without creating
  backend requests; existing preview, download, and backend-only PostgreSQL
  export contracts remain intact.

## Verification

- Passed 606 Python tests across common, attribution, standard, recommendation
  and backend suites; 106 frontend tests; and 10 specification/preflight tests.
- The complete backend suite reported 143 passing tests. With the pinned
  simulator checkout present, all 31 focused Data Generator tests passed.
- The dashboard suite reported 132 passing tests, including the mounted editor
  and page, stale-response guards, static unavailable state, selector locking,
  active-mode idempotence, and final run-issue forwarding. Production Vue and
  static builds passed with only the existing Plotly chunk-size warning; browser
  checks passed at 610px and 1280px for both reviewed variants.

## Limits

The unchanged Knowledge Base importer encounters a Windows file-lock error in
the local Nextcloud directory; complete frontend builds were verified in Linux
containers. No importer behavior was changed to work around that issue.

The supplied external host job failed before frontend compilation because its
generator configuration was missing. The release preparation procedure is
documented, but the external job configuration and server were unavailable for
editing or rerunning. This patch does not certify a live deployment or semantic
completeness of every existing specification.
