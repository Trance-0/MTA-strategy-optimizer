# Version 0.9.13

Date: 2026-08-17

## Changes

- Moved `docs/en/environment/` to `docs/en/introduction/environment/` (Environment is a subsection of Introduction, not a sibling of it) and renamed `docs/en/strategy_recommendation/` to `docs/en/strategy-recommendation/` (matching the hyphenated convention every other section directory uses). File contents are unchanged; only the paths moved.
- Fixed `docs/.vitepress/config.mts`: removed the now-stale `en/environment` sidebar scan block — Environment is picked up automatically as a nested folder of the `en/introduction` scan now that it lives at `docs/en/introduction/environment/` — and repointed the `en/strategy_recommendation` scan block's `scanStartPath`, `resolvePath`, and `rootGroupLink` to the renamed `en/strategy-recommendation` directory. This scan-path mismatch was the direct cause of `ENOENT: no such file or directory, scandir 'docs/en/environment'` on `npm run build`/`dev`, which was also why `run-doc-site.bat`/`.sh` would not start.
- Fixed the internal links the reorganization left broken: root-relative and relative links to the old `/en/environment/` and `/en/strategy_recommendation/` paths across `docs/en/` and the repository-root `README.md`, plus three `../environment/`-style links inside `docs/en/introduction/environment/amc-mta-usage.md` whose correct relative depth changed when that file moved one directory level deeper (into `introduction/`).
- Hardened `docs/run-doc-site.bat`: every failure path (missing Node.js or npm, a failed `npm ci`/`npm install`, a failed `npm run`) now falls through to a shared `:fail` label that calls `pause` unless `DOCS_NONINTERACTIVE=1` is set, mirroring the pattern already established in `dashboard/run.bat`, so a window opened by an Explorer double-click no longer closes instantly on error. A Ctrl+C stop of the `dev`/`preview` server (exit code 0 or 130) is not treated as a failure and does not pause.

## Verification

- `npm run build` in `docs/` completed with no `ENOENT`, dead-link, or sidebar-scan error.
- `docs\run-doc-site.bat build` completed end to end with exit code 0.
- `docs\run-doc-site.bat --help` still exits 0 without pausing.
- Ran `run-doc-site.bat build` with Node.js removed from `PATH`: it printed the diagnostic and exited 1 immediately under `DOCS_NONINTERACTIVE=1`, and by code inspection falls through to `pause` instead of exiting when that variable is unset.
