# Versions 0.9.3–0.9.4

Date: 2026-08-12

Archived summary of two adjacent patches, consolidated to retain the ten-page version-log limit.

## Version 0.9.3 — Authoritative Gitee synchronization

- Made the Gitee mirror preserve its protected `master` branch as an exact alias of GitHub `main`, preventing Gitee from rejecting a protected-current-branch deletion.
- Force-updated every GitHub branch and tag on Gitee, pruned non-GitHub refs except the protected `master` alias, and added an exact object-ID verification gate.
- Added a textual progress bar to the live Actions log and a persistent progress table to the GitHub Actions run summary.
- Added the strategy-evaluation framework, strategy-loader, and strategy-structure design documentation to the English site navigation.
- Moved the implementation specification catalog into the introduction section, corrected its campaign-hierarchy terminology, and updated the links that pointed at its old location.
- Added the external user-interface design prototype supplied in the working tree.

## Version 0.9.4 — Documentation as ground truth

### Governance

- Established specification-oriented programming as a repository rule: `docs/en/` is the ground truth, code implements the specification, and a disagreement between them is a code defect unless the user says otherwise. Agents must not silently rewrite a page to match drifted code.
- Required a `compact` frontmatter field on every page, defined as a routing signal dense with real identifiers so an agent can read only the `compact` fields to decide which pages a task needs. Added it to all 98 pages.
- Recorded that each implementation page is the code-level specification for the files it names, carrying the behavior contract those files must satisfy, and that code-level specification must not be collected in a separate project-wide catalog.
- Recorded `modules/mta_strategy_evaluation/` as specified but unbuilt, so its empty directory is not mistaken for the current design.

### Navigation

- Removed the project-level implementation specification catalog; code-level specification moved onto the page describing each file.
- Merged the Workspace and Product sections into Overview, shortening the navigation bar from twelve entries to ten, and deduplicated the five overlapping index pages into one.

### Code and documentation reconciliation

- Corrected the touchpoint key from `PRODUCT:...` to the actual `AD_PRODUCT:FORMAT:PLACEMENT:CREATIVE:INTERACTION_TYPE`, and replaced stale model-comparison statistics with the values the shipped summary file contains.
- Corrected the documented inputs, outputs, dependencies, and verification notes across the hierarchy validator, budget recommender, dataloader, evaluation, output contract, model registry, attribution model interface, and the model pages; expanded the strategy Campaign output example to every key the generator emits.
- Removed the orphaned `modules/mta_attribution/run_pipeline.py`, a tracked duplicate of `script/run_pipeline.py` that contradicted the rule centralizing commands in `/script`, and restored the canonical `initial_budget_recommendation.json` required by `--check-output`.

## Verification

- `uv run python -X utf8 -B script/generate_initial_budget.py --check-output` reported `fixture_matches: true` and `output_matches: true`.
- All three module suites passed: 160 attribution, 90 standardized-interface, and 34 strategy tests, for the documented 284 total.
- `npm run build` in `docs/` completed with no dead links after the section merge and page deletions.
- The mirror workflow compared Gitee branch and tag object identifiers against the authoritative GitHub references after every synchronization.
