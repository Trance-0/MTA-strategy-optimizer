# Version 0.9.30

Date: 2026-08-26

## Changes

- Fixed the navigation rail losing its grouping on a narrow viewport. When 0.9.26 turned the vertical rail into a horizontal bar below `1024px`, it hid the group headings with `.nav-label { display: none }` on the reasoning that a heading in a row reads as an item itself. The grouping was left to be carried "by order alone", which in practice meant it was not carried at all: OVERVIEW, PLANNING, and INSIGHTS vanished and the six views ran together as one undifferentiated strip, so a reader on a tablet or a phone met a flat list where a reader on a desktop met three named sections.

- Each group of more than one view now collapses into a labelled disclosure rather than spilling its items into the row. The three section names survive the breakpoint, and a view is reached through the section it belongs to exactly as in the column. A group holding a single view is not given a disclosure — opening a list to choose its only entry is friction — so Command Center stays a button on the bar itself.

- Moved the open/closed state into `SidebarNav.vue`, which watches the breakpoint with `matchMedia`. Collapsing a group is a change of behavior rather than of appearance, and CSS alone cannot hold the state a disclosure needs. The width is now stated in both the component and the stylesheet, so `dashboard/tests/dashboard.test.js` asserts the two have not drifted apart rather than letting a stylesheet edit silently strand the component at the old width.

- Gave the disclosure the closing routes a reader expects — Escape, an outside click, and choosing a view — and made widening past the breakpoint close any open group, so a panel cannot strand itself over a column that is already showing its items. A closed group carries the active state when the current view is inside it, so the reader's position is never hidden by a shut group. The panel is absolutely positioned and floats over the content, because a bar that reflowed the page on every open would be the tall block the bar exists to avoid.

- Kept the group names at the narrowest width. Below `620px` the view labels still go and the bar is icons only, but a bare chevron names nothing, and the group name is the only thing identifying a section once its items are behind a disclosure. Inside an open panel the labels return, since a panel is a list with the width for them and is unreadable without them.

- Published the two stack images to the GitHub Container Registry as `ghcr.io/trance-0/mta-backend` and `ghcr.io/trance-0/mta-dashboard`, built by the new `.github/workflows/publish-containers.yml` from the same two Dockerfiles the local stack uses. The stack can now be run on a host with neither a toolchain nor the sources.

- Made the trigger the `VERSION` file rather than the commit. A published image is identified by the version it was built from, so rebuilding on every push would produce many images claiming to be the same version and leave the tag meaning "whichever build ran last". `paths: VERSION` restricts the workflow to the pushes that touch the file, and a first job asks the registry whether both tags already resolve — so a push that touches `VERSION` without changing its content publishes nothing, and a tag is written exactly once. `workflow_dispatch` takes a `force` input for the one case that must overwrite a tag deliberately.

- Gated the publish on the suites that own the code each image ships, and gated the result on a pull. The `verify` job runs on a runner that never built the images: it pulls both, starts them through `run.sh pull` rather than a second description of it, and asserts `/api/health` directly and through the client's proxy, the client document, and the full `/api/dashboard` snapshot. The build job proves an image was pushed; only a pull from a machine that never built it proves it can be consumed.

- Gave `deploy/docker/` a `pull` mode beside `up`, so the same `compose.yaml` either builds from the checkout or runs the published images. Each service's `image` is the GHCR reference in both modes, which is what stops a built image and a pulled one from being confused at the same version. `pull` fails with the remedy rather than falling back to a build, since silently building a version that was supposed to be released hides the thing worth knowing. Both modes now wait on the health checks with `up -d --wait`, so a caller that continues to a request is not racing the start.

- Committed `modules/mta_strategy_recommendation/outputs/campaign_strategy.json`, which had been gitignored while `initial_budget_recommendation.json` beside it was not. Twelve `mta_strategy_evaluation` tests read it, and passed only because the file happened to exist untracked on the machine that generated it; the class covering it already described itself as testing "both artifacts this repository actually commits". The gap reached the images too: `.dockerignore` does not exclude `modules/`, so a local build copied the artifact into the API image and a CI build did not, and one version tag could have described two different images depending on where it was built. The document is synthetic throughout, so tracking it is the same call already made for the budget seed.

- Made the test gate skip what belongs to another repository rather than fail for its absence. `external/mta_sim_dataset` is a separate project vendored as a submodule, and the workflow checks out this repository alone; the one generator test and the ten response-pipeline tests that need its checkout now skip with the reason. A suite reporting on this project should fail for a defect in this project.

- Fixed `deploy/docker/run.bat` failing with "cannot find the batch label - describesource" for a label plainly present in the file. `cmd.exe` seeks a label by byte offset and re-reads the file as it goes; in an LF-only script that seek can land mid-line, and adding `pull` mode changed the offsets enough to break it. The file was LF only because `.gitattributes` covered every other text type but not `.bat`, so the previous version had been working by luck. `*.bat text eol=crlf` makes the checkout CRLF while the stored blob stays LF, which is why the fix shows no diff in the other three batch files.

## Verification

- Twenty-seven dashboard tests pass, one of them new: that the bar collapses each multi-page group instead of flattening it, covering the `display: contents` column layout, the positioned panel, the single-page exemption, the `aria-expanded` and `aria-controls` contract, the closing routes, and the listener cleanup.

- Driven in a real browser at 1440, 900, and 560 pixels against the committed snapshot, with **zero console, page, or network errors**. At 1440 the rail is unchanged: three static headings and six visible items. At 900 and 560 it is a 53-pixel bar carrying two disclosures, and opening PLANNING reveals exactly Budget Manager, Campaigns, and Campaign Optimizer, adds no height to the bar, and overlaps the content rather than displacing it. Choosing Campaigns navigates to `#campaigns`, closes the panel, and leaves PLANNING marked as current. Escape and an outside click both close it. Resizing from 900 to 1440 with a group open returns six visible items, three static headings, and no open group.

## Known Gaps

- The disclosure opens on click alone. Arrow-key traversal within an open panel, and a focus trap while it is open, are left to the browser's default tab order.

- `docs/version/` now carries six flat patch pages, two more than the four the file-management rule keeps outside a minor-version folder. Moving `0.9.25` and `0.9.26` into `0.9/` is a documentation-structure change with its own cross-reference edits and is deliberately not bundled into this fix.
